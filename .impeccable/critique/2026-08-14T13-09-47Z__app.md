## Design Specificity Verdict

## Overall Impression

The homepage establishes calm authority and the history route rewards exploration with real content. The main opportunity is journey continuity: users need a truthful return path, while unfinished first-class destinations should not feel like dead ends.

## What's Working

- Gold is used as orientation and affordance rather than decoration.
- The homepage has a clear dominant action and low visual noise.
- Public and restricted content are separated clearly, building trust without exposing private material.

## Priority Issues

### [P1] Return control does not respect the visitor's path

**Why it matters:** A visitor arriving at História from another page, search result or link cannot return to that context through the site control.

**Fix:** Enhance the contextual return link to use browser history when available and retain Home as the no-JavaScript or direct-entry fallback.

**Suggested command:** `$impeccable polish`

### [P1] First-class navigation includes unfinished destinations

**Why it matters:** Instituições, Publicações and Contato have equal navigation status but lead to the same construction state, creating a perceived dead end.

**Fix:** Either hide unready destinations or replace each with an approved minimum useful page. This requires approved institutional content or a navigation policy decision.

**Suggested command:** `$impeccable clarify`

### [P2] Mobile navigation presents too many simultaneous choices

**Why it matters:** Seven public links plus the restricted area are flattened into one menu.

**Fix:** Prioritize core visitor paths and group the remaining destinations after a content-readiness decision.

**Suggested command:** `$impeccable distill`

### [P2] Agenda recovery is page-wide

**Why it matters:** API failure recovery reloads the whole page without retry feedback.

**Fix:** Retry in place with loading and disabled states; surface freshness when available.

**Suggested command:** `$impeccable harden`

### [P3] Mobile PDF reading depends on an embedded reader

**Why it matters:** Device PDF behavior varies.

**Fix:** Make the full-screen PDF route at least as discoverable as the embedded reader on small screens.

**Suggested command:** `$impeccable adapt`
